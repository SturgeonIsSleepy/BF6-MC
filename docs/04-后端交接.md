# 后端交接文档

给接手后端（KubeJS 玩法逻辑）的人。

**当前状态**：能跑通，但有 3 类值需要现场标定才能真玩。
**你的主要工作**：把占位值换成真值，然后打磨玩法。

## 1. 你的战场：一个文件

```
kubejs/server_scripts/bf6.js      2087 行 / 67 KB
```

**只有这一个文件。** 直接改，不要拆。

⚠ KubeJS 会加载 `server_scripts/` 下**所有** `.js`。拆成多个文件会重复注册
`ServerEvents.tick` / `EntityEvents.hurt`，表现为「一进服就疯狂刷报错」。

## 2. 状态机（先看懂这个）

```
LOBBY ──(全员 ready + 已选图模式)──> BRIEFING ──(10s)──> PLAYING ──(胜负/超时)──> RESULT ──(15s)──> LOBBY
```

`ServerEvents.tick` 每 20 tick（1 秒）跑一次，按 `global.BF6.state` 分发：

```js
switch (global.BF6.state) {
    case S.LOBBY:    onLobbyTick(server);    break
    case S.BRIEFING: onBriefingTick(server); break
    case S.PLAYING:  onPlayingTick(server);  break
    case S.RESULT:   onResultTick(server);   break
}
```

每个阶段的逻辑在 `global.BF6._lobbyTick` / `_briefingTick` / `_playingTick` / `_resultTick`，
由各分区挂载。**加新阶段就在这里加 case + 挂一个 `_xxxTick`。**

### 全局状态在哪

```js
global.BF6 = {
    state,        // 当前阶段
    tick,         // 全局 tick 计数（所有计时都基于它）
    timer,        // 当前阶段剩余秒数
    match,        // 当前对局对象，null 表示没在对局
    players,      // username -> 玩家对象
    vote,         // { map, mode, votes }
    readySet,     // username -> true
    readyCount,   // 派生值，由 recountReady 算
    bots,         // { bf6_red: number, bf6_blue: number }
    lastResult    // 上一局结算快照
}
```

⚠ 跨文件/跨事件只能通过 `global.BF6` 传状态。KubeJS 的 `global` 不是 JS 全局作用域，
`global.foo = function(){}` 之后裸调用 `foo()` **不会**解析到它 —— 这是本项目踩过的坑。
所以内部函数都用裸 `function foo(){}` 声明，靠单文件同作用域可见。

## 3. 必改：三处占位值

### 3.1 地图坐标（最重要）

`global.BF6.maps` 里 4 张图的 `spawns` / `flags` / `br` / `vehicles` 全是设计值：

```js
urban: {
    spawns: {
        bf6_red:  { x: 8120, y: 70, z: 8000, yaw: -90 },
        bf6_blue: { x: 7880, y: 70, z: 8000, yaw: 90  }
    },
    flags: [
        { id: 'A', x: 8060, y: 68, z: 8000, r: 14, name: '码头' },
        ...
    ],
    br: { cx: 8000, cz: 8000, r0: 220, rEnd: 40 },
    vehicles: [
        { type: 'iv:mtank', x: 8100, y: 70, z: 8020 },
        ...
    ]
}
```

**怎么改**：进游戏站到红队出生位置，按 F3 抄坐标，替换数字。占领点同理。
半径 `r` 是**球形**（三维距离），室内点建议 10-12，开阔地 14-16。

四张图目前是 `8000/16000/24000/32000` 为**方块坐标**原点各占一块，
互不干扰。如果你只做一张图，把其它三张从 `maps` 里删掉即可（`rollRandomMap` 会自动适配）。

### 3.2 TaCZ 枪械 ID

`LOADOUTS` 里的 `tacz:modern_kinetic_gun{GunId:"tacz:ak47",...}` 是推测值。
TaCZ 1.1.4 的默认枪包不一定有 `ak47` / `mp5` / `m249` / `m700` / `ump45`。

**怎么查**：

```
/give @s tacz:modern_kinetic_gun
```
拿到枪后看 tooltip（`showGunIdInTooltip = true` 时显示 ID），或解包
`.minecraft/tacz/` 下的枪包目录看 `data/<ns>/guns/*.json` 的文件名。

弹药 ID 同理：`tacz:ammo{Type:"tacz:762x39"}` 里的 `Type` 要对应实际弹药。

### 3.3 IV 载具实体 ID

`iv:mtank` / `iv:car` / `iv:heli` 也是推测值。

**怎么查**：
```
/summon iv:
```
按 Tab 看补全列表。IV 的载具 ID 取决于装了哪个内容包
（官方 OCP / UNU Military / Vell's），不同包 ID 不一样。

## 4. 已知未实现 / 半成品

按优先级排。这些是「想让它像战地」还缺的：

### 4.1 AI 不会占点（优先级最高）

现在 `maintainBots` 只保证每队有 N 个 AI 站着打，AI 不会主动走向据点。
征服模式里 AI 对票数毫无贡献。

**思路**：在 `tickConquest` 里每 5 秒给 AI 下移动指令。Recruits 支持编队和移动命令，
但脚本侧调用方式需要在游戏里试（`/recruits` 的子命令 + NBT）。

### 4.2 没有部署界面

战地最标志性的是「大地图选出生点」。现在固定从队伍出生点复活。

**思路**：`respawnConquest` 里判断玩家是否按了某个键（或用了某个物品），
弹一个聊天框可点的据点列表（`tellraw` + `clickEvent` 调 `/bf6 spawn A`），
然后传送到该据点。

### 4.3 兵种只是发不同装备

没有兵种技能（医疗兵加速救人、工程兵快速修载具等）。
`LOADOUTS` 只是物品表。

**思路**：在 `reviveScan` 里判断救人者兵种是 `medic` 就缩短救援时间；
工程兵靠近载具时给 `effect give ... haste`。

### 4.4 载具伤害没接

IV 的 `AllowExternalDamage` 已在 `config/README.md` 里写了要开，
但 TaCZ 子弹打载具的判定没做任何特殊处理，全靠 IV 自己的 hitbox。

### 4.5 大逃杀没有地面战利品

只有空投箱（`dropAirdrop`）。落地后除了初始的石剑和面包，没东西可捡。

**思路**：`startBattleRoyale` 里在地图上撒箱子，或者监听 `BlockEvents.rightClicked` 在
特定方块上生成战利品。

### 4.6 结算面板是纯文字

`renderResultPanel` 用 `tellraw` 一行行打表格，没有 GUI。
想做好看得写 `ServerEvents.commandRegistry` 之外的自定义 GUI（KubeJS 1.18 支持有限）。

## 5. 调试手段

### 5.1 快速验证流程

```
/bf6 status                       # 看当前状态
/bf6 start conquest               # 跳过大厅直接开征服
/bf6 start br                     # 直接开大逃杀
/bf6 stop                         # 中止 → 15s 结算 → 回大厅
```

### 5.2 重载脚本

```
/reload
```
KubeJS 支持热重载，但 **`global.BF6` 不会重置** —— 改了状态机相关逻辑要
`/reload` 后手动 `/bf6 stop` 回到大厅，或重启服务器。

### 5.3 日志

```
logs/kubejs/server.log
```
`console.info('[BF6] ...')` 的输出都在这。脚本报错也在这，搜 `bf6.js`。

### 5.4 语法检查（提交前必做）

```bash
node --check kubejs/server_scripts/bf6.js
```

CI 也会跑，另外还查：占位符残留、重复函数声明、内部函数是否都有定义、
素材是否齐全、文档是否引用了已删除的文件。

## 6. 代码约定

### 6.1 命名

| 前缀 | 含义 |
|---|---|
| `_xxxTick` | 阶段钩子，挂在 `global.BF6` 上 |
| `startXxx` | 开局函数 |
| `tickXxx` | 每秒逻辑 |
| `renderXxx` | 只读渲染（HUD/面板） |
| `xxxOf` / `xxxPlayers` | 查询 |

### 6.2 命令执行

全部用 `server.runCommandSilent()`，不要用 `server.runCommand()`（会刷屏）。

### 6.3 玩家名获取

**不要**直接写 `player.username`。KubeJS 在不同事件里给的包装类型不一致，
用 `nameOf(entity)`：

```js
function nameOf(entity) {
    if (!entity) return null
    try { if (entity.username) return String(entity.username) } catch (e) {}
    try { if (entity.name && entity.name.getString) return entity.name.getString() } catch (e) {}
    try { if (entity.displayName && entity.displayName.getString) return entity.displayName.getString() } catch (e) {}
    return null
}
```

血量同理用 `healthOf(entity)`。

### 6.4 坐标必须是整数

`/setblock` 只接受整数。`/tp` 接受小数但没必要。
大厅坐标曾经用了 `8.5` / `-8.5`，导致讲台静默不生成 —— 已修，别再犯。

### 6.5 权限

`/bf6` 根节点**不加** `requires`。只有这 5 个是 OP 专属：
`start` / `stop` / `map` / `bot` / `lobby`。

`vote` / `class` / `ready` 必须开放给所有人 —— 大厅讲台的 `clickEvent`
是以**点击者身份**执行的，加权限会让非房主点了没反应。

## 7. 前后端接口

前端（`fancymenu/`）和后端（`bf6.js`）是**松耦合**的，只有这几处交界：

| 前端元素 | 后端对应 |
|---|---|
| 主菜单「多人对战」按钮 | 无（只开 Multiplayer 屏） |
| 模式卡「征服」 | `Action: Run Command` → `/bf6 start conquest` |
| 模式卡「大逃杀」 | `Action: Run Command` → `/bf6 start br` |
| 地图卡（4 张） | 无直接绑定，大厅里投票选 |
| 大厅（游戏世界内） | `buildLobby` 建的虚空平台 + 讲台 |
| HUD 底板（`hud_*.png`） | **不用于 FancyMenu**，是给自绘 GUI 的参考 |
| 局内 HUD | `updateSidebar` + `bar()` + `title()` |
| 结算 | `renderResultPanel` |

⚠ **HUD 底板那 6 张 PNG 现在没有被任何代码使用**。它们是设计稿，
真要在游戏里画出那种效果，得写自定义 GUI 渲染（KubeJS 1.18 能力有限），
或者接受「用 title/actionbar/scoreboard 拼出来」的近似版本 —— 现在的实现是后者。

## 8. 交付检查表

提交前跑一遍：

```bash
node --check kubejs/server_scripts/bf6.js
```

然后确认：

- [ ] 没有 `{{` 占位符残留
- [ ] 没有重复的顶层 `function` 声明
- [ ] 新增的内部函数都有定义（CI 会查白名单里的 64 个）
- [ ] 改了 `MAPS` 的话，`scripts/gen_all.py` 里的 `MAPS` 也同步（否则卡片和地图对不上）
- [ ] `docs/` 里没有指向已删除文件的引用

CI 会替你跑上面这些，推上去看 Actions 绿不绿就行。

## 9. 快速上手建议

1. 先读 `bf6.js` 的 `ServerEvents.tick`（约 240 行）和 4 个 `_xxxTick`，理解流程
2. 进游戏 `/bf6 start conquest`，看能不能跑完一局
3. 修地图坐标（3.1），这是「能不能真玩」的分水岭
4. 修枪械/载具 ID（3.2、3.3），这是「手感对不对」的分水岭
5. 从 4.1（AI 占点）开始加玩法

有问题看 `docs/01-安装.md` 的故障表，或者 `logs/kubejs/server.log`。
